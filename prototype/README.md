# Eurogold brickwork payments: prototype

A working prototype of the bricklayer claims process for EG587 Old Hall Road, Bromborough,
loaded with the real plot list, tender allowances, ledger bookings and bricklayer rates.

Open `Eurogold-Brickwork-Payments.html` in any browser (phone or PC). Use **Viewing as** at
the top to switch between Bricklayer, Foreman, QS and Accounts.

## The flow

1. **Bricklayer** picks one or more plots. For each plot it shows the allowance, what's
   already booked (by anyone) and what's left. They enter quantities and add photos (at
   least one per plot), answer the four pre-start checks, optionally split the payment,
   then sign and send. Anything over the allowance needs a reason.
2. **Foreman** completes the seven sign-off checks, then approves or sends it back with a comment.
3. **QS** sees the claim against the allowance with any overs flagged, can amend quantities,
   then approves or sends it back. Approving posts the quantities to the plot ledger.
4. **Accounts** gets the payment run: everything approved before Thursday 10:00, by person,
   with splits applied. Export to CSV or print.

## Files

- `app.html`: the app (HTML, CSS, JS, no dependencies)
- `data.js`: seed data, generated by `build_data.py` from the Excel files
- `build_data.py`: reads the Brickwork Ledger and the rates workbook, plus a few site photos for the demo claims
- `build.py`: inlines `data.js` into `app.html` to make the single file
- `Eurogold-Brickwork-Payments.html`: the single-file build to share

Rebuild:

```
python3 build_data.py "EG582 Brickwork Ledger.xlsx" "Up To Date Bricky Rates.xlsx" photo1.jpg photo2.jpg photo3.jpg > data.js
python3 build.py
```

## Prototype limits

Everything is stored in the browser on one device. There are no logins, and nothing is
shared between phones. The production version needs real accounts, a shared database and
photo storage. It could be built on Microsoft 365 (SharePoint and Power Apps) or as a
hosted web app.
